Como usar com segurança

  1. Baixe o arquivo JSON e guarde em local protegido.
  2. Antes de restaurar, suba uma cópia do sistema em ambiente separado.
  3. Execute as migrations nesse ambiente limpo.
  4. Restaure com python manage.py loaddata caminho_do_backup.json.
  5. Confira login, produtos, estoque, vendas, caixa e relatórios antes de qualquer uso real.

Proteção dos dados

O arquivo pode conter dados comerciais, clientes, vendas, estoque, logs e usuários técnicos do sistema. Não envie esse backup por canais abertos.

A restauração direta pela tela fica desativada de propósito: supermercado não pode correr o risco de sobrescrever uma base real por engano.

Antes da primeira execução, use {{ backup_local_script }} {{ backup_validacao_flag }} para conferir banco, mídia, logs, destino e a cadeia fiscal sem gerar o pacote. O resultado sanitizado é registrado para o Master pelo comando {{ backup_evidencias_comando }}.

O destino pode ser definido por {{ backup_destino_env }}. A tarefa automática usa a conta {{ backup_conta_tarefa }} e não depende de usuário conectado.

Em produção, configure {{ backup_criptografia_env }} para gerar o pacote .zip.aes. Use {{ backup_criptografia_flag }} quando a política exigir apagar o .zip aberto.

A cópia secundária fica desligada por padrão. O Master define {{ backup_destino_secundario_env }} para uma pasta de NAS, rede ou disco externo e confirma com {{ backup_destino_secundario_confirmacao_env }}=True ou {{ backup_destino_secundario_confirmacao_flag }}. Somente o pacote criptografado e seu SHA-256 são promovidos.

Depois de homologar o agendamento, o Master pode definir {{ backup_idade_maxima_env }} com o prazo máximo em horas. O valor 0 mantém o alerta de atraso desligado.
